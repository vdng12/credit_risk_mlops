## 2. The Paradigm Shift

| Before (docker-compose) | After (kind-first) |
|---|---|
| `docker compose up -d` | `kind create cluster && ops/scripts/apply-all.sh` |
| Compose services map 1:1 to containers | Services are K8s StatefulSet/Deployment resources |
| `risk-net` bridge network | Kind's built-in network (containers reachable by service name) |
| Port mappings hardcoded in compose | Port mappings in `kind.yaml` (node `extraPortMappings`) |
| Volumes managed by compose | PersistentVolumeClaim per stateful service |
| SQL scripts mounted via `volumes:` | SQL scripts loaded via ConfigMap or PVC init |
| Dev ≠ Prod (different stacks) | Dev = same manifests, prod = different values (same shape) |

## 6. Credential Strategy

Credentials stay in `.env` at the project root (same as before). Manifests reference them via **Helm-style value injection** or `envsubst` in `apply-all.sh`:

```bash
# ops/scripts/apply-all.sh pattern
for dir in ops/k8s/*/; do
  envsubst < "$dir/manifest.yaml" | kubectl apply -f -
done
```

This keeps `.env` as the single source of truth — no hardcoded secrets in manifests.

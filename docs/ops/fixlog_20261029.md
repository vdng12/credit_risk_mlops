## 1. Indexed deterministic RNG (Phase 0)

The sequential random tape was replaced with per-(entity, month) streams.

| Item | Before | After |
|---|---|---|
| RNG | one shared sequential generator (`seed+2`) | `randstreams.month_rng(seed, entity, month)` - a month's content is a pure function of (seed, entity, month) |
| Ledger | sequential bootstrap tape | `advance_month` re-derives its generator per month from the root seed |
| Replay/resume | not reproducible per month | byte-identical month replay, idempotent retries (regression tests) |

## 9. Issues surfaced by the wire test

- **F1** monthly snapshot PK collision (`clients_pkey` across months /
  reruns) - append-only OLTP + stable client ids. Needs upsert /
  snapshot-keyed raw-row decision (new ADR).
- **F2** offline exact-duplicate leaks into the online lane (injection
  before lane routing) - offline problems must mutate only batch
  artifacts (triggers the Problem-interface split ADR).
- **F3** duplicate replay would collide with OLTP PKs - Debezium keys by
  PK, so at-least-once replay must be a transport-level topic re-emit.
- **F4** burst as implemented repeats identical rows (wrong model) - a
  spike must scale generation with distinct ids.
- **F5** SQLAlchemy executemany param logging noise (cosmetic).
- **F6** connector re-registration after cluster recreate (ops reminder).

Full detail: `docs/datgentor_challenges_issues_20261029.md`.

# CDC Setup — 2026-10-26

## Architecture

```ascii
postgres-source ──► Debezium Connect ──► Redpanda topics
  (WAL logical)        (connector)         (one topic per table)
```

Every INSERT/UPDATE/DELETE on the source Postgres is captured from its
write-ahead log and published as a JSON event to a Redpanda topic.

---

## Services

### postgres-source (already deployed)

Updated to enable logical replication:

```yaml
command:
- /usr/local/bin/docker-entrypoint.sh
- postgres
- -c
- wal_level=logical
- -c
- max_replication_slots=1
- -c
- max_wal_senders=1
```

The entrypoint path is explicit because Kubernetes's `command` overrides
both ENTRYPOINT and CMD (same reason SeaweedFS needs `/entrypoint.sh`).

Verify:

```bash
kubectl exec <pod> -- psql -U lending -d lending_db -c "SHOW wal_level;"
# → logical
```

### Debezium Connect

**Manifest:** `infra/k8s/debezium/manifest.yaml`
**Image:** `debezium/connect:2.6`
**Port:** 8083 (REST API)
**Bootstrap:** `redpanda:9092`

Debezium connects to Redpanda as its Kafka broker and Postgres as its source.

```yaml
env:
- name: BOOTSTRAP_SERVERS
  value: redpanda:9092
- name: CONFIG_STORAGE_TOPIC
  value: debezium-config
- name: OFFSET_STORAGE_TOPIC
  value: debezium-offsets
- name: STATUS_STORAGE_TOPIC
  value: debezium-status
```

### Connector registration

**Script:** `ops/k8s/register-connector.sh`

Registers a single Postgres connector that watches 5 source tables.
Runs from inside the debezium pod via `kubectl exec`:

```bash
bash ops/k8s/register-connector.sh
```

**Connector config:**
- `plugin.name: pgoutput` — Postgres logical decoding plugin
- `table.include.list` — `clients, loan_applications, application_decisions, payments, card_authorizations`
- `tombstones.enabled: false` — no tombstone events emitted
- `slot.name: dbz_slot` — replication slot name
- `publication.name: dbz_publication` — publication name

| Table | Redpanda topic |
|---|---|
| clients | `lending.public.clients` |
| loan_applications | `lending.public.loan_applications` |
| application_decisions | `lending.public.application_decisions` |
| payments | `lending.public.payments` |
| card_authorizations | `lending.public.card_authorizations` |

Topic naming convention: `<topic.prefix>.<schema>.<table>`

---

## Event format

Standard Debezium JSON envelope. Example (abbreviated):

```json
{
  "payload": {
    "op": "c",
    "before": null,
    "after": { "client_id": "CDC-TEST-001", "credit_score": 680, ... },
    "source": { "db": "lending_db", "table": "clients", "lsn": 27157448 }
  }
}
```

| `op` | Meaning |
|---|---|
| `c` | Create (INSERT) |
| `u` | Update |
| `d` | Delete |
| `r` | Snapshot (initial read) |

## Usage

```bash
# Watch CDC events for clients
kubectl exec <redpanda-pod> -- sh -c 'rpk topic consume lending.public.clients -f "%p %t %o\n" --timeout 10'

# Check connector health
kubectl exec <debezium-pod> -- curl -s http://localhost:8083/connectors/lending-cdc-connector/status
```
